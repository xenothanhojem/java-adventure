12.1 Introduction 
This Learning Unit requires that you are familiar with Boolean Logic in Learning Unit 6 in Exploring 
IT: Theory Grade 10. 
Instead of data being stored in text files and the data in these files being manipulated, using 
programs, data can be stored in tables in a database, using a database program and manipulated 
using Structured Query Language (SQL). 
A database is "a collection of related information about a subject, organised in a useful manner" 
according to QUE's Computer and Internet dictionary. The data in the database can be easily 
retrieved and used to draw conclusions, or to make decisions using a database program. A relational 
database program provides mechanisms to store data in tables and relate the data in one table to 
another using a common column or field. Most major commercial databases created using programs 
such as Microsoft Access or MySQL use a relational approach.  
A Database Management System (DBMS) is a 
set of programs used to create the database, 
control the database, provide access to it and 
manage the data within the database.  
A good DBMS should avoid duplication of data 
and should provide data that is consistent and 
reliable. Many users usually have access to the 
same database, possibly across a network. The 
DBMS needs to control the access to the data. 
Microsoft Access and MySQL are examples of a 
DBMS. MS Access is proprietary software 
developed for the Windows operating system and 
is not designed for commercial use. MySQL is an 
open source DBMS that is designed for 
commercial use and multiple operating systems. 
Both support Delphi and Java, however MySQL 
supports a larger range of programming 
languages. If you do not have a licenced version 
of MS Access, then you can freely download and install MySQL instead. In this Learning Unit, we will 
use Java DB which is bundled with NetBeans which is freely available. 
In this chapter, we will learn how to structure the data in a database and later on, in Grade 11, how to 
write programs that will use and manipulate the data. We will be using MS Access and MySQL 
applications in the examples. Application programs can connect to any other type of database with 
minimal changes.

12.2 Database Concepts 
A DBMS schema is the skeleton structure or the logical design of the entire database. It defines how 
the data is organised into tables and how these tables are linked together to form relationships. The 
simplest entity in a database is a field. A field can store a single data item. Fields are the columns in 
a table. For example, a field can be a person's name, date of birth (an age is never stored, but this will

a variable needs a type in a programming language. 
When many fields are grouped together, they form a record. All the related fields containing data 
about one person will form a record. In a database table, records are the horizontal rows. 
As another example, think of a record as a list of your personal details at your school. All the 
information stored at the school about you is grouped together as a record. Each student record 
consists of many fields storing information about a student such as StudentID (one word – just like 
any variable name), name, surname, grade, date of birth and address. 
12.2.1 Primary Keys 
The StudentID field is a very important one – it's known as the Primary Key. A Primary Key is 
defined as being a field that uniquely identifies each record in the table. Consider the table 
containing students (as above), what would happen if you wanted information about a particular 
student, but more than one student has the same name or surname?  The DBMS wouldn't be able to 
differentiate enough to guarantee that you are working with the correct record unless you provide 
more information, like grade, but you could still have more than one student with the same name, 
surname and grade. What if you wanted to edit or delete a particular student?  If you don't have a 
Primary Key, you may delete more than one student or edit the incorrect student!  
We are going to design tables that include a Primary Key, and we have the option of using an auto 
number Primary Key; we are going to make use of this design feature when we create the first 
database that you will use. 
12.2.2 Database Terminology 
Many records can be grouped together in a table. A physical paper file containing many peoples' 
records, or a drawer of a cabinet containing all the library cards, can be thought of as in a similar way 
to a table. 
• A field stores a single data item. 
• A record is a collection of fields. 
• A table is a collection of records. 
• A database is a collection of tables. 
• A primary key uniquely identifies a record.

• UpDown: This field represents a Boolean value. Each Comrades Marathon alternates 
between being an uphill race (Durban to Pietermaritzburg) or a downhill race (Pietermaritzburg

format.

of 50 should be long enough to accommodate any name and surname.

field type), or vice versa, but it's somewhat discriminatory to refer to a gender as either True or 
False. A Text type of 'F' or 'M' is more appropriate and is set to a field size of 1 for a single 
character allowing for a variety of genders. 
• Club:  This field name doesn't represent a reserved word conflict. Once again, a Text field size 
of 50 would cover all possibilities. 
• Country:  This field name doesn't represent a reserved word conflict and a Text field size of 
50 would also suffice.

12.4 Creating Queries 
SQL stands for Structured Query Language. SQL contains a set of commands that are used to 
access and modify the data in a relational database. This language is used by many database 
programs. There are many versions of SQL, but all versions use the basic statements in a similar 
way. The SQL statements are processed by the DBMS.  
SQL statements are the means by which queries or updates are performed on the database. It is 
important to remember that when you are using advanced SQL statements, different versions of SQL 
may return slightly different results. The versions of SQL may also differ slightly to produce slightly 
different commands. 
A query is used to search or extract data from a table in a database based on specified criteria.

12.6.2 Sorting using ORDER BY 
By inserting ORDER BY into an SQL statement, we can produce a query that is sorted. A simple SQL 
statement to sort data in ascending order will be:  
SELECT <field(s)>  
FROM <table>   
ORDER BY <field>; 
For example, to sort tblComrades' data in alphabetical order of WinName, the SQL statement would 
be:

SELECT *  
FROM tblComrades  
ORDER BY WinName; 
If we wanted to reverse the order and list the WinNames from Z down to A, then the SQL statement 
would be: 
SELECT *  
FROM tblComrades  
ORDER BY WinName DESC; 
DESC indicates the table is to be sorted in descending order according to the field. By default, the 
column is ordered in ascending order ASC, so it would make no difference if we used: 
SELECT *  
FROM tblComrades  
ORDER BY WinName;  
 
OR  
 
SELECT *  
FROM tblComrades  
ORDER BY WinName ASC; 
There are many winners from the same country, so we may want to show a list of winners from each 
country, ordered by the country name and then by the winner's names within that country. We can 
extend the SQL statement to sort according to a first field and then a second one. This means if there 
is more than one runner from the same country, then the records with the same country will also be 
sorted according to their names.

12.6.3 Conditions using WHERE 
We can limit the number of rows in the table by specifying criteria that must be satisfied in the result. 
Supposing we want to display the records in the table tblComrades for a specific set of years, say 
2000 onwards. 
The SQL statements we have been working with so far can only be used to select columns from a 
table and display all the data in those fields. If we want to find records for the years 2000 onwards, we 
need to include a condition: 
The SQL statement for this query is: 
SELECT *  
FROM tblComrades  
WHERE RaceYear > 1999; 
Bear in mind, the condition RaceYear > 1999 could have been replaced with RaceYear >= 2000. All 
the Boolean comparison operators >, <, <=, >=, <> can be used in WHERE conditions. 
The WHERE clause is added to the SQL statement to include a condition. 
SELECT <field(s)>  
FROM <table>   
WHERE <condition>;

12.8.4  Changing the Details in a Field 
If a Comrade's Marathon winner is stored with the wrong details, or one of the fields needs to be 
changed, the most obvious way is to change the values of the record in the table in MS Access; 
however, a SQL statement can also be used to alter the fields in a record.

UPDATE <table>  
SET <column/field name> = <new value>  
WHERE <column/field name> = <existing value>; 
Once again, a WHERE clause should be included, otherwise all the records will change. 
If you want to change a single record, it's always better to refer to the Primary Key in the WHERE 
clause; this will guarantee that only 1 record will change.

WHERE ID = 8; 
OR 
UPDATE tblComrades  
SET WinName = 'Charly Dollar'  
WHERE WinName = 'Charly Doll';
